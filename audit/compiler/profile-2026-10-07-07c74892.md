Date: 2026-10-07

## Scope And Method

This report profiles M1 `07c74892`, the consolidation onto one pipeline. No
later commit changes executable compiler code: Q8 adds repro inputs and Q9's
generated diagnostic file is not wired into the crate. The comparison
baseline is [`98cdb947`](profile-2026-10-07-98cdb947.md).

The release driver benchmark ran 200 and 2,000 functions per folder, or
3,009 and 30,009 lines. Each number is the median of five processes covering
cold, warm, all-private-body, and comment edits. The checked-in signature
harness measured a public-signature-and-caller edit once at each size.

The release `hd` binary ran all six samples, four hand-written benchmarks,
and the generated 10,000-line package on V8 through Node. Those numbers are
medians of five runs after one warm-up. `hd build` is seven measured runs
after one warm-up.

Samply is installed, but recording failed with `Unknown(1100)`. macOS
`/usr/bin/time -l` also could not read kernel data. Named native samples,
allocation counts, and peak RSS are therefore **no data**; the hot-function
ranking uses the driver's stage timers. Those timers no longer report Parse
separately.

## Findings

1. **Atrocious implementation slip:** 36.3% of the 30k serial cold run is
   outside named stages, alongside 4,001 per-instance emission tasks. Replace
   those tasks with the designed folder-group unit before tuning emission.
2. No other path is atrocious. Warm time is unchanged, edit paths are linear,
   and the eight-worker pool makes the cold run 2.04× faster.
3. The consolidated full parser and interface path explain much of the
   non-cold regression. The intended fixes remain the skim/header path and
   fast manifest key, not micro-optimization.
4. Invalidation stays narrow at codegen: 2 of 4,001 instances re-emit after
   the public signature-and-caller edit, and none after a comment edit.
5. Native sampled symbols, allocations and peak RSS remain measurement gaps;
   stage ownership is the strongest evidence available on this host.
