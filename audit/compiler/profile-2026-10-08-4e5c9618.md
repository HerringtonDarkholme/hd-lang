# Compiler Profile: `4e5c9618`

Date: 2026-10-08.

Status: measurement only; nothing here changes accepted behavior. This
checks the compiler with the `missing-trait-method` body-stage check
(`hd_check/src/conform.rs`: a written impl must write every trait
method with no default body, reported at the impl header) against
[Resolution And Interfaces](../../future-work/compiler/resolution-and-interfaces.md),
[Scheduler](../../future-work/compiler/scheduler.md),
[Cache](../../future-work/compiler/cache.md), and
[Codegen](../../future-work/compiler/codegen.md).
The comparison is the previous committed report,
[`6c886735`](profile-2026-10-08-6c886735.md).

## Scope And Method

Same harness and method as the previous report:
`bench/profile-signature` at 200 and 2,000 functions per folder (3,009
and 30,009 generated lines, plus embedded std), median of five
processes; signature edits in fresh processes; `hd run` / `hd build` on
the samples through the spec CLI forms (five runs after one warm-up,
seven fresh builds). No harness changes were needed this time.

Samply still fails on this host and macOS exposes no counters, so
native symbols, allocations and peak RSS remain **no data**. Rankings
use the driver's stage timers. Load stayed under 13 for the harness
runs.

## Findings

- Nothing to flag: every stage, sample and pool ratio is within noise
  of the previous report. The `missing-trait-method` check is a
  per-impl-header scan in the body stage with no measurable cost on
  these inputs.
- The untimed remainder (scheduler/graph/cache/driver, 57.90 ms cold)
  stays the largest single row with no function-level owner; sampled
  symbols would still be the way to split it.
