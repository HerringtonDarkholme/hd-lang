## Scope And Method

This report profiles M3 `20ea6342`, where std interfaces and the real
prelude enter every program. The comparison is the previous committed
report, M1 `07c74892` (earlier reports are in git history). M2 changed only
the parser between those points.

The existing generated benchmark became invalid under M3 because functions
named `f32` and `f64` shadow prelude types. The checked-in profiling harness
now renames only those two benchmark functions. It otherwise uses
`hd_driver::bench::sources` unchanged.

The release harness ran 200 and 2,000 functions per folder, or 3,009 and
30,009 generated lines, plus embedded std. Each result is the median of
five processes. Signature edits ran in fresh processes; other edit cases
share the cold process's memory cache.

The release `hd` binary ran each sample and realistic input on V8 through
Node. Results are five runs after one warm-up. `hd build` is seven runs
after one warm-up.

Samply still fails on this host with `Unknown(1100)`, and macOS does not
expose the required counter data here. Native sampled symbols, allocation
counts and peak RSS are therefore **no data**. The hot-function ranking uses
the driver's stage timers.

## Findings

1. **Atrocious warm-path regression:** the 3,009-line warm run is 12.7×
   M1. Unchanged std is skimmed and its interface, header-check and
   coherence tasks run again. The designed stat manifest and reusable std
   pack are the fixes; micro-tuning these stages is not.
2. **Existing atrocious cold overhead remains:** 33.3% of the 30k serial
   cold run is outside named stages alongside 4,001 per-instance emission
   tasks. Group emission by codepack as already designed.
3. No generated-size path is superlinear. The fixed std workload makes
   10× more generated source cost 1.8× to 6.2× wall time.
4. V8 execution and `hd build` show no material regression. Generated
   code invalidation remains precise.
5. Native sampled symbols, allocations and peak RSS remain measurement
   gaps on this host.
