# Implementation Gap Audit (2026-10-10)

What the Rust `hd` (main `fa387b6f`) lacks against the frozen spec, ranked
by what stops someone writing and shipping a real program. Method:

- Every `r[...]` rule in `spec/lang`, `spec/std`, `spec/cli` (5896) classified
  by its fixtures (from the `# Spec ...: rule.id` headers and
  `cli-cases.tsv`) and by citations in `compiler/crates`, `compiler/host`,
  `lib/std`: 3296 pass, 518 fail or partial, 488 cited only, 1594 neither.
  "Neither" is noisy (member access shows 17 such rules and works), so each
  weak section below was probed by hand.
- The 41 example programs (website tour, playground, `examples/`) run on the
  Rust `hd` and the TS oracle: identical stdout for all 41.
- A two-package workspace from `hd new --lib` / `hd new --app` with a path
  dependency: `hd run`, `hd build`, `hd test` (incl. the scaffolded
  `hd_run!` test), `hd check`, and the prebuilt `.wasm` all work.
- The 373 failing conformance fixtures split into 91 valid programs that
  fail and 282 invalid programs with a missing (130) or wrong (152)
  diagnostic. The 84 `unsupported` ones were rerun to name the construct.
- Speed: a 123-line program compiles and runs in 0.26 s cold, 0.06 s warm;
  hello world is 5209 bytes of Wasm.

## Tier 4: missing errors (accepts or misreports invalid programs)

282 fixtures (#203–#214, #224, #232). Soundness-relevant first: rows inside
type arguments unchecked and no-common-type (#204, 13), identity on
non-references (9), sealed traits (6), private type leaks (6), overlapping
or orphan impls (3). The rest give a wrong or missing code on code that is
already wrong.

## Not needed for CLI programs yet

Wasm boundary for host embedding (module.host.*, Registration, Host Results,
~40 rules); determinism rules; performance (fine at this size, #215).

## Recommended order

1. F1 fetch core (#250), then F2 `hd add`/`hd update` (#251).
2. Parse error messages, and `hd check` running every stage (#220): small,
   and every user hits them.
3. Tier 2 constructs, grouped one feature per task: typed derivation;
   explicit type arguments on a type; mixed variant fields; `...=`;
   suspension in `and`/`or` and guards; suspending function values.
4. W2–W5, so `hd` ships without Node.
5. `--release` (#200), REPL (#240), `hd doc`, `hd fix`, `hd cache gc`.
6. Tier 4 errors, soundness first.

## Probed rules (M12, 2026-10-10)

Neither-rules of `spec/lang/04-type-system.md` through
`07-functions.md` (315 + 235 + 147 + 135 = 832 by the audit's
fixture-and-citation method) probed against the TS prototype, one
minimal probe per observable behavior (pure definitions skipped).
Probes in `.probes-m12/ch04–ch07/` (uncommitted). Classes: (a) Rust
rejects valid, (b) Rust accepts invalid, (c) different output; code-only
mismatches (both reject, Rust names another code) follow per chapter.
Byte-identical valid runs are parity and unlisted.

### 04 — proche 125, divergences

- (a) `types.option.nest.accept`: `fn nest(n: i32?) -> i32??: n`
  rejected `type-mismatch` (explicit `.Some` forms parity).
- (b) `types.generic.infer.join.not-lct`: `pick(count, found)` accepted
  with expected type (TS `type-mismatch`).
- (b) `types.lct.no-combine`: `[small, wide]` (`mut` × plain) accepted
  (TS `no-least-common-type`); Rust infers the upgraded element type.
- (b) `types.literal.float-finite` ×2: `let x: f32 = 1e40`,
  `let x: f64 = 1e999` accepted (TS `float-literal-range`); Rust runs
  and prints `inf`.
- (b) `types.map-key.float-no-hash`: `Map[f32, i32]` accepted
  (TS `unsatisfied-trait-bound`, no `Hash`).
- Code-only (Rust rejects, other code): contextual `.None`/`.Ok`/joins
  → `cannot-infer-type`/`type-mismatch` (want
  `missing-contextual-enum-type`); heterogeneous joins → `type-mismatch`
  or `implicit-narrowing` (want `no-common-type`); signed+unsigned →
  `type-mismatch` (want `mixed-signedness`); trait-value joins →
  `type-mismatch` (want `no-common-type`); `mut` map key →
  `unsatisfied-trait-bound` (want `invalid-map-key`); representation
  variance → `type-mismatch` (want `variance-representation-change`).
- Message-only: `types.literal.int-diagnostic` (no range/fix-it),
  `types.num.no-implicit.fix` (no `write i64(…)` hint).
- Parity-but-questionable: `types.generic.default.argument-wins`
  (both infer `usize`, reject; spec example shows valid).
- Not reached (~180): `mut`/readonly paths, most bounds/defaults,
  `infer.*`, string encodings, release arithmetic.

### 05 — probed 112, divergences

- (b) `expr.arith.unary-minus`: `-(2 + 2)` on unsigned accepted, panics
  at run (TS `type-mismatch`).
- (b) `expr.range.bound.integer`: `0.5..x` accepted
  (TS `type-mismatch`).
- (b) `expr.is.incompatible`: `user is order` accepted
  (TS `incompatible-identity-operands`; spec example is an error).
- (b) `expr.member.no-field-call` + `stored-fn.error`:
  `button.on_click(41)` accepted (TS `unknown-method`).
- (b) `expr.pipe.slot.closure`: placeholder in inline closure accepted
  (TS `pipe-placeholder-in-closure`).
- Code-only: `pipe.slot.one` → `placeholder-outside-pipe` (want
  `duplicate-pipe-placeholder`); `.None == .None` → `cannot-infer-type`
  (want `missing-contextual-enum-type`); `u32..i32` → `type-mismatch`
  (want `mixed-signedness`); `collect(nums..., 4)` → Rust
  `duplicate-argument` per the spec example while TS says
  `nonfinal-positional-spread`.
- Missing warning: `expr.ord.unsigned-zero` + 4 forms (values agree,
  Rust emits no `unsigned-comparison-always`).
- (c) Panic presentation: same `index-out-of-bounds`, Rust prints
  `panic: …` exit 3, TS `file:line:col: …` exit 1.
- (a) none found. Not reached: `try` advanced, custom `Index`, `&&`/`||`
  isolation, remaining custom operators, method references.

### 06 — probed 119, divergences

- `flow.match.payload.unknown`: `Pair(missing=v, …)` misses the pattern
  error, reports knock-on `unknown-name` (TS `unknown-data-field`).
- `flow.unreachable.infinite-loop` + `unreachable.warning`: code after
  `while true:` gets no `unreachable-code` on Rust (TS warns).
- `flow.panic.report.fallback` (+ `.fix`): same `integer-overflow`
  category, Rust omits the required fallback note and suggestion.
- `flow.for.binding`: `x = x + 1` on a for-binding accepted (TS
  `non-reassignable-binding`; spec direction ambiguous — reported
  without adjudicating).
- `flow.match.data.nominal`: `Other { name }` on `User` → Rust
  `unreachable-match-arm` on `_`, TS `type-mismatch` on the pattern.
- `flow.match.contextual`: `.Some(x)` on `i32` → Rust
  `unknown-variant` + knock-on, TS `missing-contextual-enum-type`.
- `flow.match.payload.name-mismatch`: both accept and print alike; TS
  warns `variant-binding-name-mismatch` ×2, Rust silent.
- `flow.if.value.else`: both reject; Rust `missing-return-value`
  downstream, TS `type-mismatch` naming the rule.
- `flow.for.not-iterable-or-iterator`: untyped `+1` iterable accepted at
  check (fails later in Body); typed `i32` is parity. Root cause looks
  like literal inference, not the loop rule.
- Valid runs byte-identical throughout. Not reached (7):
  `for.no-root-grant`, `match.bind.generic`, `match.data.bind-primitive`,
  `bind-composite`, `readonly-mut`, `generic`, `public`.

### 07 — probed 80, divergences

- (b) `fn.name.no-overloading`: two `fn value` accepted
  (TS `duplicate-module-name`).
- (b) `fn.vararg.type.kinds`: `values...: i32` accepted
  (TS `type-mismatch`).
- (b) `fn.generic.explicit.row-dollar`: `run::[Log]()` bare row arg
  accepted (TS `generic-kind-mismatch`).
- (a) Recursive closures (`fn.recursion.closure.*` ×7): `sum := fn…sum…`
  rejected `unknown-name` (`:=` and `let`); TS runs (prints 15).
  Invalid side also code-mismatched (`unknown-name` vs
  `recursive-function-needs-result-type`).
- (a) `fn.type.suspend.weaken` + `.ctor`: `plain(fetch)` rejected
  `type-mismatch` (TS ok).
- (b) `fn.closure.needs-annotation`: unannotated param, no expected
  type, accepted (TS `closure-parameter-needs-annotation`).
- (b) `fn.local.private`: `pub fn` inside a function accepted
  (TS `syntax-error`).
- Code-only: `fn.default.later-parameter` → `unknown-name` (want
  `binding-not-yet-visible`); requirement-free defaults →
  `missing-requirement` (want `requirement-in-default`) and
  `bang-call-outside-suspension` (want `suspension-forbidden-context`);
  `List[_]` → `syntax-error` (TS `unknown-type`; spec names no code).
- Not reached: `fn.type.ctor.*` corners, `fn.capture.*`, `fn.multi.*`,
  `fn.entry.*`, `fn.param.*`, variance-repr, trailing blocks.
