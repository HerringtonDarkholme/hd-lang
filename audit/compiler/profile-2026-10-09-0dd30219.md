# Compiler Profile: `0dd30219`

Date: 2026-10-09.

Status: measurement only; nothing here changes accepted behavior. This
checks the compiler with the work since `d449ed27` (the previous
report, `audit/compiler/profile-2026-10-09-d449ed27.md`): O13
(folder-cycle recovery, #133) is the only `compiler/` change, against
[Resolution And Interfaces](../../future-work/compiler/resolution-and-interfaces.md),
[Scheduler](../../future-work/compiler/scheduler.md),
[Cache](../../future-work/compiler/cache.md), and
[Codegen](../../future-work/compiler/codegen.md).

## Scope And Method

Same harness and method as the previous report:
`bench/profile-signature` at 200 and 2,000 functions per folder (3,009
and 30,009 generated lines, plus embedded std), median of five
processes; signature edits in fresh processes; `hd run` / `hd build` on
the samples through the spec CLI forms (five runs after one warm-up,
seven fresh builds). No harness changes.

Samply still has no usable run on this host and macOS exposes no
counters, so native symbols, allocations and peak RSS remain **no
data**. Rankings use the driver's stage timers. Load ran 9–17
through the bench window; medians are tight (30,009-line cold
265–279 ms; warm 22.2–23.0 ms, confirmed by a second five-run
window at 21.6–22.4 ms).

22.38 ms (+3.7 ms, +19%), confirmed by a second five-run window
(22.16 ms) and present in the pool executor too (12.26 → 16.13 ms),
so it is systematic, not a spike. No single stage owns it —
representative warm stages move Skim 12.1 → 11.9 (flat), FolderIface
2.4 → 3.0, Coherence 0.9 → 1.3, the rest within ±0.3 ms, with the
balance in untimed scheduler/cache/driver overhead. O13's
folder-cycle recovery is the only change in range and the natural
suspect (recovery bookkeeping on the folder graph path, which warm
runs still traverse), but the attribution is unproven. At +3.7 ms
absolute on a cache-hit path — and with cold, the path that
dominates real builds, flat — this stays below the flag bar: a watch
item, not a flag.

## Findings

- Nothing to flag. One watch item: the 30,009-line warm path gained
  ~3.7 ms with no single owning stage; O13 folder-cycle recovery is
  the suspect. Revisit only if it grows again or shows up on cold.
- The untimed remainder (scheduler/graph/cache/driver, 59.76 ms cold)
  stays a top-two row with no function-level owner; sampled symbols
  would still be the way to split it.
