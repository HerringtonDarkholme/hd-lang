# Current Compiler: Emitter And Runtime Analysis

Status: observational audit at `caac922a`, 2026-10-04. Nothing here is accepted behavior or an owner decision.

Scope: [src/emitter](../../src/emitter/), its handwritten WAT runtime, [wasm.ts](../../src/wasm.ts), and host execution in [compiler.ts](../../src/compiler.ts). References: [types](../../spec/lang/04-type-system.md), [control flow](../../spec/lang/06-control-flow.md), [functions](../../spec/lang/07-functions.md), [data](../../spec/lang/08-data-and-enums.md), [traits](../../spec/lang/09-traits.md), and [requirements](../../spec/lang/11-requirements-and-suspension.md).

The emitter has 8,354 TypeScript lines outside runtime and 858 lines in its runtime directory. Its entry is `emitWat(HirProgram, EmitOptions)` through [index.ts](../../src/emitter/index.ts).

## Backend Sequence

| Order | Operation | Result |
| --- | --- | --- |
| 1 | `emissionReachability` | Selected functions, closures, implementations, globals, and dynamically called trait methods. |
| 2 | `collectModuleTypes` | Closure-signature and provider-context type registries. |
| 3 | Build suspension plans | CFGs for suspending functions containing child drives. |
| 4 | Create `FunctionEmitter` | Shared module lookup tables and adapter registries. |
| 5 | Emit module declarations and code | Types, globals, imports, functions, adapters, host factories, runtime fragments. |
| 6 | `linkWat` | WAT with unreferenced backend declarations removed. |
| 7 | `assembleWat` | Binaryen parsing, feature selection, validation, encoding, host-engine validation. |
| 8 | `instantiate` | Wasm instance, JavaScript imports, initialization, replay/provider state. |

HIR reachability happens after checking every declaration. It reduces emitted code, not frontend checking cost.

User functions remain roots even when no hd call references them, preserving host-callable functions. Compiler-generated and std functions have different rooting rules.

Reachability preserves original declaration indices. Replay identities, call targets, and generated symbolic names cannot rely on dense renumbering.

## Emitter Composition And State

The base-to-derived inheritance chain is:

```text
EmitterContext
  ValueComparisonEmitter
    IteratorEmitter
      DataEmitter
        CallableAdapterEmitter
          FunctionBodyEmitter
            FunctionEmitter
```

This is a dependency/inheritance listing, not hd code.

[context.ts](../../src/emitter/context.ts) owns declaration lookup tables, type mappings, provider keys, adapter registries, loop/cleanup stacks, temporaries, current requirements, and current function identity. It is shared while emitting a module.

Function emission resets temporary types and cleanup frames. Adapter registries and requested runtime helpers accumulate across functions and are emitted at module scope.

This is not a stateless HIR visitor. Emitting an expression can allocate a temporary, register an adapter, request a helper, or depend on surrounding cleanup and loop state.

| File | Main burden | Contract to inspect when changing it |
| --- | --- | --- |

## Runtime Representations

The mapping comes from `EmitterContext.watType`, `scalars.ts`, and type declarations in `emitReachableWat`.

| hd/HIR value | Wasm representation | Consequence |
| --- | --- | --- |
| `bool`, `char`, integers up to 32 bits | `i32` | Width and signedness are semantic properties beyond the Wasm storage type. |
| `i64`, `u64` | `i64` | Host and replay conversions must preserve unsigned bits. |
| `f32`, `f64` | Native Wasm float | Decimal display/parsing can cross JavaScript host functions. |
| `string` | GC struct containing byte array, start, length | String views can share bytes; literals still generate allocation code. |
| Tuple | `$hd.list`, an `anyref` array | Elements use erased storage and may require scalar boxes. |
| `List[T]` | `$hd.vector` with size and `anyref` array | Concrete scalar lists also use boxes. |
| `Map[K,V]` | `$hd.map` with ordered entry arrays, hash buckets, chains, Eq/Hash callbacks and contexts | Ordered iteration and hashed lookup coexist. |
| Ordinary data | Indexed GC struct | Generic fields retain their declared erased representation. |
| Ordinary enum | Indexed GC struct with tag and field layout | Tag and payload accesses depend on checked HIR layout. |
| Optional/erased result carrier | `$hd.variant` with tag and erased payload | Payload extraction needs boxing/unboxing and representation-aware tests. |
| Function value | Closure struct with typed function reference and environment | Concrete/erased callable conversions may need thunks. |
| Trait value/dictionary | Trait-specific struct with receiver, bound pack, live method references, parents | Dictionary layouts depend on module reachability. |
| Captured mutable local | `$hd.cell` containing mutable `anyref` | Shared state survives closure escape and suspension. |
| Requirement-row pack | Linked `$hd.providers` nodes | Lookup traverses keys; concatenation recursively copies the left pack. |
| Concrete suspension | Function-specific frame struct | Parameters, dictionaries, providers, child state, locals, and results remain GC roots. |
| Stored suspension | `$hd.suspension` plus adapters | Poll/cancel/result are erased behind a uniform interface. |
| Host provider | `externref`, wrapped as needed | JavaScript objects participate in the runtime ABI. |

The backend predominantly uses erased generic code and adapters. It does not generate a full separately optimized body for every concrete type instantiation.

Some layouts are module-specific: unused dynamic trait methods are omitted. An instance's generated dictionaries are therefore not a separately versioned external binary ABI.

## Ordinary Function Generation

`FunctionEmitter.emitFunction` chooses internal names, parameters, bound dictionaries, requirement providers, locals, closure environments, and export wrappers. Host-safe eligibility is narrower than the language type system.

Generic parameters and erased fields are boxed at storage/call boundaries. `HirTypeSubstitution` preserves concrete binder information where callable adapters need it.

[callable-adapters.ts](../../src/emitter/callable-adapters.ts) generates closure thunks crossing concrete and erased function ABIs. Module signature collection also shares layouts for supported representation-preserving function conversions.

### Evaluation Order

`emitOrderedArguments` stages written arguments in temporaries when parameter reordering, defaults, or explicit staging requires it. The setup executes in source order; the final operand list follows parameter order.

Default helpers receive the already evaluated earlier parameters and their bounds. This keeps caller-side named argument layout separate from evaluation order.

The direct fast path emits operand expressions in their original order. Suspension CFG lowering must maintain the same contract when an operand pauses.

### Cleanup

`emitBlock` collects deferred suites in cleanup frames. It saves a block's result in a temporary before cleanup when necessary.

Return, break, and continue emit appropriate exit cleanups before transfer. Loop boundaries determine how far cleanup unwinds.

Suspending code uses cleanup information recorded by CFG lowering and cancellation paths. Ordinary cleanup generation alone is insufficient to reason about cancellation.

### Numeric Operations

[sized-numeric.ts](../../src/emitter/sized-numeric.ts) implements width checks, wrapping, casts, shifts, and sized arithmetic. `numeric.ts` supplies widths, signedness, and native Wasm categories.

The release option selects wrapping arithmetic and masked shifts where specified. The assembly stage does not call Binaryen optimization methods.

## Suspension Lowering

[suspension.ts](../../src/emitter/suspension.ts) contains a continuation-based `SuspensionPlanBuilder`. It produces indexed blocks, synthetic locals, suspension sites, and explicit terminators.

| Plan element | Examples | Purpose |
| --- | --- | --- |
| Operations | Assign, evaluate, cleanup, provider entry, context creation, match binding | Work performed before choosing the next transition. |
| Ordinary terminators | Jump, branch, match test, complete, unreachable | Make control flow explicit. |
| Suspension terminator | Child drive, result local, next block, cleanups | Save a resumable boundary. |
| Propagation terminator | Success tag/payload, continuation, cleanups | Route success or exit the enclosing frame. |

Comprehensions become sequential loops. Nested operand evaluation, short-circuiting, branches, patterns, provider installation, and propagation have dedicated lowering cases.

A suspending function without child drives uses a simpler support path. A suspending body with any child drive uses the CFG path, including direct child calls.

### Frame And Polling Contract

`emitCfgSuspensionSupport` stores all non-parameter declared locals plus plan temporaries. It also retains parameters, generic dictionaries, requirement providers, closure environment, child frames, and result.

No per-suspension liveness calculation chooses only locals needed after a pause. This confirms the mechanism behind the existing dead-local-retention finding.

The frame uses numeric states: cold `0`, actively polling `1`, complete `2`, cancelled `3`, a pending control state `4`, and child-resume states starting at `5`. Generated trace events expose lifecycle transitions separately.

Resume dispatch uses nested `if` chains keyed by site state. CFG dispatch also tests block IDs through emitted `if` forms.

Repeated storage code writes frame locals when returning pending. Code size therefore depends on both suspension sites and stored-local count.

Cancellation selects the active child, cancels it, and runs registered cleanups. Cold cancellation skips unreached work; completed/cancelled states enforce the runtime's lifecycle checks.

The generated drive loop polls synchronously until ready. The development exports permit manual polling, but the compiler does not supply a general asynchronous wake scheduler.

This audit confirms these mechanisms. It does not remeasure the old cubic-code-size or dispatch-cost claims.

## Reachability And WAT Linking

[reachability.ts](../../src/emitter/reachability.ts) follows resolved function, closure, global, dictionary, default-helper, iterator, and suspension references. It tracks live trait methods alongside live implementations.

The handwritten runtime and newly generated adapters contain dependencies that do not appear as direct HIR function calls. [link-wat.ts](../../src/emitter/link-wat.ts) therefore performs a second reachability computation over backend declarations.

The WAT parser handles quoted strings and nested comments. Exported declarations, start, and active initialization segments root the graph.

`elem declare` is validation metadata, not an execution root. Its retained references follow live `ref.func` targets.

The linker keeps original source slices and symbolic IDs. It prunes functions, imports, globals, and recursive type members without positional renumbering.

Binaryen subsequently parses linked WAT again. The two parses have different jobs; removing the structural linker requires another way to select backend/runtime dependencies.

## Host And Runtime ABI

The ABI spans [host-providers.ts](../../src/emitter/host-providers.ts), [compiler.ts](../../src/compiler.ts), [host-functions.ts](../../src/host-functions.ts), and WAT runtime fragments. `host-boundary.ts` centralizes the shared shape dispatch.

Scalar values, UTF-8 strings, result tags/payloads, structural node trees, function/site indices, provider keys, and poll outcomes cross this boundary. Checker capability validation constrains which declared signatures can use it.

Strings cross as bytes. Structural results have recursive validation/decoding for optionals, tuples, lists, and data, with generic substitution performed by each recursive consumer.

Replay encodes wide integers as decimal text and floats by bits. Provider configuration identity, operation identity, function code identity, arguments, and outcomes are checked against recorded events.

Function code identity hashes source slices. It does not recursively hash the semantic dependencies of a function; the existing F-401 report still describes that limitation.

`compiler.ts` recomputes reachable host method information during instantiation. The emitter and runtime must agree on import names and selected methods.

### Handwritten Runtime

| Fragment | Responsibilities |
| --- | --- |
| `runtime.wat` | Provider packs, vectors, iterators, host string conversion, panic expectation and supporting runtime operations. |
| `map.wat` | Hashing, bucket selection, collision chains, ordered entries, insertion/removal, equality callbacks, reindexing. |
| `boundary.wat` | Materializing host-provided structural/string boundary values. |
| `stored-suspension.ts` embedded WAT | Erased suspension adapters and task combinator polling/cancellation support. |

The current map runtime is hashed. Collision chains may degrade to scans, but unconditional linear lookup is no longer an accurate description.

## Assembly, Validation, And Errors

[wasm.ts](../../src/wasm.ts) lazily imports pinned Binaryen and parses generated WAT. It sets GC, reference, mutable-global, and nontrapping conversion features, validates, emits bytes, and checks `WebAssembly.validate`.

The Binaryen module is disposed in `finally`. Cached state is the Binaryen load promise, not the generated program module.

Assembly failures identify generated WAT or a validation stage. They are JavaScript errors rather than stable language diagnostics.

`commands/source.ts`, `reportFailure`, recognizes compiler diagnostics, supported runtime panics, and unsupported-runtime errors. Other exceptions propagate as internal failures.

This confirms the boundary behind existing F-265. A validated Wasm module also does not prove source semantics, cleanup order, or replay correctness.

## Verified Traces And Open Architecture Questions

Existing fixtures exercised cleanup, mutable capture sharing, and child suspension. Their AST-to-HIR-to-WAT traces are recorded in [findings and verification](findings-2026-10-04.md).

Focused tests passed for suspension state, cancellation, host providers, replay, reachability, WAT linking, captures, and host functions. Selected runtime conformance cases also passed.

The successor discussion needs explicit ownership of representation lowering, suspension lowering, backend dependency selection, and ABI definitions. It also needs a decision about whether module-specific layouts are internal or intended for separate compilation.

These are architecture questions raised by the current code. No replacement backend, intermediate representation, or scheduling mechanism is selected here.
