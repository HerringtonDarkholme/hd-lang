# R27: Runtime Of The Samples And Six Programs (`d67b01df`)

Method: `node compiler/bench/runtime/run.mjs` on the six programs in
`compiler/bench/runtime/progs/` (build once with
`compiler/target/release/hd` rebuilt from this commit, 1 warmup + 5
measured runs each, p50 = median; hd via `compiler/host/run.mjs`,
JS via `node v24.19.0` directly; checksums must match or the script
refuses to time — all matched), plus `hd build` + timed
`run.mjs` runs of every package sample under `compiler/samples`.
Comparison base: `runtime-vs-node-439adb05.md` (Q24) and
`runtime-hotspots-efc99933.md` (Q26). Read only; no `compiler/`
edits.

## Six programs vs Node

| Program | What it does | debug hd/JS | release hd/JS | Q24 debug |
| --- | --- | ---: | ---: | ---: |
| closures | fill 20M list, `map`/`filter`/`fold` with closures | 0.67x (366 / 547) | 0.66x (358 / 540) | 0.67x |
| int-loop | 240M `%`-heavy i32 iterations | 2.91x (2396 / 822) | 2.83x (2387 / 844) | 3.03x |
| list-sort | insertion sort of 30k pseudorandom i32 | 7.60x (1339 / 176) | 7.98x (1351 / 169) | 7.76x |
| map-count | 200k inserts + 5k reads on `Map[i32, i32]` | 1.09x (37 / 34) | 1.12x (38 / 34) | 59.97x |
| string-build | 40k `out + "abcdefgh"` appends | 79.64x (2532 / 32) | 67.49x (2521 / 37) | 82.36x |
| trait-dispatch | 80M generic calls through a bound | 1.50x (881 / 587) | 1.56x (883 / 567) | 1.52x |

Times are p50 ms (hd / JS). Geomean hd/JS: **3.53x debug, 3.47x
release** (was 7.00x / 6.97x).

Headline: **map-count is fixed, 60x → 1.1x.** The #124 hash table
(Map iteration, removal and non-int/string keys, codegen.md §13.12)
replaced the per-op boxing + double-lookup path Q26 attributed 98%
of the old ~2000 ms to; 200k inserts now run in 37 ms against
Node's 34 ms. No profiling needed beyond the ratio: the old hot
function is gone with the old implementation.

Release still changes nothing (same Wasm either profile — the
profile does not alter codegen yet, as Q24 established).

## Samples (wasm runs)

Package samples, `hd build` then timed `run.mjs` (median of 3 runs
after warmup; node startup ~30 ms dominates every line):

data 37 ms, fib 31 ms, gaps 32 ms, generic 31 ms, init 35 ms,
std_types 32 ms, trait 33 ms (doctests/testing build no executable).
Single-file samples (`hello`, `arith`, `defer`, `err_exit`, `exit`,
`suspend`) have no package to build; through `hd FILE` (compile
included) they run ~40 ms as in the P1 passes. Outputs all match
their P1 runs. Nothing here is above trivial scale — no
order-of-magnitude problem exists to flag at this size.

## Flags

- **string-build (~68–84x) stands as the one order-of-magnitude
  problem.** Unchanged since Q22/Q24: quadratic `bytes_concat`
  append, 91.9% of time in `build` per Q26. Needs the rope/builder
  representation; no new hotspot data — reprofiling it would repeat
  Q26 byte for byte.
- map-count needs no action (fixed by #124, verified above).
- Everything else is within 8x of Node (list-sort 7.6–8.0x,
  int-loop 2.9x, trait-dispatch 1.5x, closures 0.67x) — below the
  order-of-magnitude bar, same as Q22/Q24 concluded.
