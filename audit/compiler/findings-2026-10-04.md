## New Findings

### CS-01: Defaulted Literal Spans Accumulate Across Compilations

Severity: medium, resource retention. Evidence: source-confirmed and probe-confirmed.

[literal-join.ts](../../src/checker/literal-join.ts), lines 26-30, exports a strong `Set<SourceSpan>` named `DEFAULTED_SPANS`. `markDefaultedLiteral` adds each defaulted literal's span.

[literal-retry.ts](../../src/checker/literal-retry.ts), `defaultGroupWidth`, also adds spans. No compilation boundary clears the set, and it has no eviction policy.

The probe repeatedly analyzes unchanged [literal-first-use-fallback.hd](../../spec/conformance/typing/valid/literal-first-use-fallback.hd) in one process. Six analyses produce no diagnostics and the following sizes:

| Completed analyses | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Retained span entries | 0 | 12 | 24 | 36 | 48 | 60 | 72 |

This proves accumulation of strongly retained span objects, not a measured heap-size increase. Spans can also contain physical source-origin/document references.

The related HIR expression/local registries use weak collections. That does not make `DEFAULTED_SPANS` weak or compilation-scoped.

Impact: memory growth in the REPL, browser workers, in-process test workers, and repeated API calls. A fresh process per invocation hides the accumulation.

Owner question: should literal metadata belong to a compilation context, or have object-lifetime ownership through weak storage? Neither mechanism is implemented by this audit.

### CS-02: Derivation Diagnostic Registries Reuse Keys Without Compilation Identity

Severity: medium correctness risk. Evidence: source-confirmed and helper-level probe-confirmed; no end-to-end wrong-program diagnostic reproduced.

[derive-intrinsics.ts](../../src/checker/derive-intrinsics.ts), `SpanOrigins` and `SpanOriginSet`, stores origins in process-global maps/sets. Keys come from [diagnostics.ts](../../src/diagnostics.ts), `sourceSpanKey`.

That key uses physical file path and start/end offsets. It includes neither source content identity nor compilation identity; direct parsing has no physical document path.

The helper probe parses an existing derivation fixture, copies a field span, and queries its diagnostic before registration. It returns `unsatisfied-trait-bound` with the supplied message.

After registering a field origin at the same coordinates, the same helper query returns `derive-field-missing-trait`. Its message names the previously registered field and owner.

Observed key: `\u0000` followed by `61:72`. The exact remapped message is:

```text
field 'number' of 'AuditOrigin' does not implement Eq, which @derive(Eq) requires
```

This fence contains diagnostic output, not hd code. The probe's registration isolates the helper contract; it does not establish a faulty normal compilation sequence.

Impact: earlier derivation facts can be indistinguishable from coordinates in later input. Same-path edits are also not differentiated by the key.

Owner question: where should derivation origins live, and what source identity must their keys retain across edits? Changing those contracts is outside this audit.

### CA-01: Flattened Package Identity

Evidence: source-confirmed; existing package integration tests pass for implemented behavior. Existing gaps are already tracked under P2, EMB-S, QUALIFIED-PATH, and related tags.

[package.ts](../../src/package.ts) parses files, resolves uses, computes initialization groups, and joins reachable source. [commands/source.ts](../../src/commands/source.ts) supplies that joined text to compilation.

The checker then works in one namespace. Package name collisions and incomplete privacy are consequences of this representation, not just missing import syntax.

Some source locations are restored by linker segments, while std uses symbol-backed origins. A successor must make those identities explicit before deciding reuse/incremental boundaries.

### CA-02: Textual Types And Semantic Cycles

Evidence: source-confirmed. Existing speed finding F3 covers the cost concern; this audit does not repeat its historical speedup estimates.

`ValueType = string`; [types.ts](../../src/types.ts) scans nested syntax, and [checker/shared.ts](../../src/checker/shared.ts) resolves/matches/substitutes it. Backend layout also branches on the same spellings.

Value imports connect `shared.ts` to `literal-join.ts` and `map-keys.ts`, while those modules import `shared.ts`. Literal joining reaches least-common-type, variance, and assignability, returning to shared helpers.

The cycle is organizational evidence, not a reproduced module-initialization failure. It shows that type meaning is distributed among utility, inference, conversion, and special-purpose modules.

### CA-03: Shared Checker State And Repeated Body Checks

Evidence: source-confirmed. The 18-class body-checker chain includes its base; it shares scopes, locals, captures, provider state, caches, and diagnostics.

`LazySignatures.get` can infer another function. Private row inference rechecks relevant bodies until rows stop growing; final HIR checking runs later.

Module-global map-key facts are set per program. Concurrent re-entry could replace them, although this audit found no supported current re-entry path demonstrating that failure.

The new capture view avoids repeated merged-map copying, but still refers to enclosing mutable scopes. It is an improvement within the existing ownership model.

### CA-04: Cross-Stage Representation And Distributed ABI

Evidence: source-confirmed. The [inventory script](status-quo-inventory-2026-10-04.mjs) finds these five imports crossing the documented folder boundaries:

| Importer | Internal dependency |
| --- | --- |
| `compiler.ts` | `emitter/reachability.ts` |
| `emitter/context.ts` | `checker/captured-cells.ts` |
| `emitter/function-body.ts` | `checker/captured-cells.ts` |
| `emitter/module-types.ts` | `checker/captured-cells.ts` |
| `emitter/value-comparison.ts` | `checker/standard-traits.ts` |

HIR contains cells, concrete suspension indices, dictionary plans, erased parameter information, and provider forms. This is already partly representation-oriented IR.

Suspension CFG lowering happens inside the backend. Wasm layouts, handwritten WAT operations, and JavaScript encoding/invocation must agree without one independent ABI schema.

`host-boundary.ts` usefully centralizes shape dispatch. It does not remove the remaining ABI ownership across these consumers.

### CA-05: Unequal Rollback Contracts

Evidence: source-confirmed contract; architectural risk, not a reproduced miscompilation.

`speculate` restores participating objects and preserves identity. Production participants skip immutable inputs and journal signature/inference changes.

Literal retry records array lengths and map sizes. It removes appended entries, but cannot undo overwrites or arbitrary mutations to existing objects.

Future changes must preserve the retry's append-only assumptions or change its restoration contract. Treating the two mechanisms as interchangeable would conceal that requirement.

### CA-06: Backend Dependency Selection And Retention

Evidence: source-confirmed, with reachability/linker and suspension tests passing.

HIR reachability removes unused standard code while preserving original indices and user roots. The WAT linker also removes runtime helpers, adapter dependencies, imports, and type declarations.

Generating only HIR-reachable functions therefore does not yet make `linkWat` redundant. The linker needs either preservation or an equivalent backend dependency representation.

Suspension frames store every non-parameter local plus generated temporaries. They do not calculate per-site liveness, confirming the mechanism behind F-506.

Resume/CFG dispatch uses linear chains. This audit does not claim a new complexity exponent or code-size benchmark.

### CA-07: Recovery And Failure Boundaries

Evidence: source-confirmed. These concerns overlap existing F-605, F-265, and F-155.

Parser failure prevents an AST; fatal body failure unwinds to one function's checker boundary. Signature errors prevent later body lowering.

Wasm validation checks generated code shape, not hd semantics. Its failures are JavaScript errors, and `reportFailure` rethrows unknown internal failures.

Runtime panic reporting lacks general source attribution. The portable harness's timeout can terminate a worker, but runner timeouts checked after a call cannot interrupt a body that never returns.

User bodies contain three `cell-new`, seven `cell-get`, and one `cell-set` occurrences. Counts describe tree occurrences, not dynamic allocations or executed instruction counts.

The emitter puts shared cells in closure environments. Existing runtime assertions verify persistent counter state and visibility of later writes from both closures and defining scopes.
