# Compiler Profile: `6cf2a034`

Date: 2026-10-08.

Status: measurement only; nothing here changes accepted behavior. This
checks the post-M4c compiler (checker breadth through P2-1a, `mut`
restrictions, script entries, spanned `NotImplemented`) against
[Resolution And Interfaces](../../future-work/compiler/resolution-and-interfaces.md),
[Scheduler](../../future-work/compiler/scheduler.md),
[Cache](../../future-work/compiler/cache.md), and
[Codegen](../../future-work/compiler/codegen.md).
The comparison is the previous committed report, M3
[`20ea6342`](profile-2026-10-07-20ea6342.md).

## Scope And Method

The release harness is `bench/profile-signature` at 200 and 2,000
functions per folder (3,009 and 30,009 generated lines, plus embedded
std). Each result is the median of five processes. Signature edits ran
in fresh processes; other edit cases share the cold process's memory
cache. Two bench-side repairs were needed before anything ran, both in
`bench/profile-signature/src/main.rs` only: the `Host` initializer
gained the new `render_tir` field, and the generated sources are
rewritten to reassignable `let` bindings plus a `fn main() -> void $
Console` entry, because P2-1a made `:=` non-reassignable and `println`
needs a `Console` row. The driver's own `bench` example still carries
the stale sources.

The release `hd` binary ran each sample on V8 through Node: five runs
after one warm-up (`hd build` seven after one warm-up).

Samply still fails on this host, and macOS exposes no counters here, so
native sampled symbols, allocation counts and peak RSS are **no data**,
as in the M3 report. The hot-function ranking uses the driver's stage
timers. Load stayed under 8 for the harness runs.

## Findings

- Nothing here is an order-of-magnitude hotspot in isolation: the worst
  single rows (Body +109%, Emit +156%, Link 11×) all track either
  deliberate checker breadth or 3.3× more emitted Wasm, and warm
  no-edit stays at 14 ms for 30,009 lines.
- The bench inputs themselves are the maintenance risk, not the
  compiler: the checked-in `bench/` programs, the driver's `bench`
  example sources, and once already the prelude-colliding `f32` names
  all rotted as the language moved. The profile harness now carries
  three source rewrites; the next language change that touches `let`,
  `main`, or effect rows will need a fourth unless the generated
  sources move with the checker.
- The untimed remainder (scheduler/graph/cache/driver, 57.40 ms cold)
  is the largest single row and has no function-level owner in stage
  data; sampled symbols would still be the way to split it.
