# Re-Triage The Failure Buckets (M4, 2026-10-10)

hd commit `fa387b6f`. `compiler/CONFORMANCE.md` now reads **2472 pass,
289 fail, 84 unsupported** of 2845 (the job text's 2420/336/84 moved).
21 buckets hold 3 or more cases; they cover 260 fail + 82 unsupported
cases (342 of 373, 92%). Buckets of 1-2 cases are listed in §8 without
task rows.

Method: four workers probed every case in the 21 buckets with the
release `hd` (scratch `HD_CACHE` each; single-file `hd check --tests`
approximates the harness `CheckTests` goal, `hd build`/`hd test` for
back-half stages; tree/role/layout fixtures were replicated as temp
packages). Judging rule that shapes several groups
(`conformance.rs:diagnostic_verdict`): a `reject` passes only with
**exactly one** error of the expected code on the marker line, so
duplicates, cascades and wrong codes all fail.

`[impl]` = compiler behavior missing; `[check]` = detection/diagnostic
missing or misordered. Stage is the compiler stage of the fix.

## `fail:type-mismatch` (36)

- **T1, failed joins must be `no-common-type` (11, `[check]`, check).**
  `values := [1, "one"]` reports `type-mismatch` on later elements
  instead of one `no-common-type` for the failed join. Same shape:
  heterogeneous lists/maps, closure result without common type,
  supertrait-widening joins, row-union literals, `i32??` if/else.
  Rules: `types.lct.no-common`, `types.lct.no-supertrait-widening`,
  `types.generic.infer.join.*`, `fn.closure.result-inferred.common`,
  `req.row.union.*`.
- **T2, signedness pairs must be `mixed-signedness` (4, `[check]`,
  check).** `left + right` (i32+u32), `count..limit`, `abs_diff`,
  `count_ones` comparisons. Rules: `types.num.binary.no-mix`,
  `expr.range.bound.signedness`, `std-num.abs-diff.unsigned`,
  `std-num.bits.count-ones-u32`.
- **T3, representation-changing variance (3, `[check]`, check).**
  `Producer[i32]` → `Producer[dyn Display]` and fn-result analogues.
  Rules: `types.variance.no-insertion`, `fn.type.variance-repr.excluded`.
- **T4, unmet derived bound at use (2, `[check]`, check).**
  `Box[fn() -> void] == …` reports operand mismatch, want
  `missing-derived-bound`. Rules: `trait.derive.bound-unmet`,
  `trait.derive.bounds`.
- **T5, collapse paired result/operand errors (5, `[check]`, check).**
  First code and marker line are right (`in result: expected i64, found
  i16`), but a second `in operand:` error breaks the one-error rule
  (`no-widening-operator`, `mixed-width-operands`, `usize-u32-operand`,
  `operator-left-literal`, `no-widening-float`). Rules:
  `types.num.binary.same-type`, `types.num.no-implicit`,
  `types.usize.convert`, `expr.op.left-literal.no-fit`.
- **T6, `.None` in joins (2, `[check]`, check).** `[1, .None]` and
  `if flag: 1 else: .None` report element/result mismatch, want
  `missing-contextual-enum-type` (`types.lct.contextual.error`).
- **T7, check placeholder before unification (1, `[check]`, check).**
  `apply(3, format(_, 8))`: `type-mismatch` (10:14) precedes the
  expected `placeholder-outside-pipe` (10:21)
  (`expr.pipe.placeholder-outside`).
- **T8, range-check huge literals first (1, `[check]`, check).**
  `18446744073709551616 - value` (2⁶⁴ overflows u64) yields 3×
  `type-mismatch` ("found a floating-point literal"); want
  `integer-literal-range` (`types.literal.int-range`). Also review the
  float fallback for huge literals.
- **T9, valid programs spuriously rejected (7, all `[impl]`).**
  Multi-key provider destructuring (`Left is not a tuple`, 2);
  `fn!` not weakening to its constructor type (1, `--tests` only);
  one-layer optional wrap at argument position (1, `--tests` only);
  literal-vs-associated-type inference for intrinsic methods (1,
  `--tests` only); `TestRunner`-capturing `body=fn!(…)` closures (1,
  `--tests` only); one-fit left-literal conversion for `i64(3) * price`
  (1). Rules: `provider-access`, `suspending-functions`,
  `optional-types`, `expr.op.std.intrinsic-method`,
  `std-testing.runner.body-property`, `expr.op.left-literal.join`.
