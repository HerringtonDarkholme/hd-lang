# Compiler Profile: `3b3a9181`

Date: 2026-10-09.

Status: measurement only; nothing here changes accepted behavior. This
checks the compiler with everything since `4e5c9618` (the previous
report, `profile-2026-10-08-4e5c9618.md`, deleted; git history keeps it): derived
implementations instantiate their template (#119), compiler-supplied
trait rows with codegen selection (solver §3.9, #121), per-tuple-type
`Structure` codegen (#126), the `KnownItems` coverage test (T2,
test-only), `std.sys` + `std.net` declarations and the `Backoff` /
`Rng::from_seed` additions (L2/L3, `lib/std`), plus the conformance
regen and F1 fixture signatures (no compiler effect), against
[Resolution And Interfaces](../../future-work/compiler/resolution-and-interfaces.md),
[Scheduler](../../future-work/compiler/scheduler.md),
[Cache](../../future-work/compiler/cache.md), and
[Codegen](../../future-work/compiler/codegen.md).

## Scope And Method

Same harness and method as the previous report:
`bench/profile-signature` at 200 and 2,000 functions per folder (3,009
and 30,009 generated lines, plus embedded std), median of five
processes; signature edits in fresh processes; `hd run` / `hd build` on
the samples through the spec CLI forms (five runs after one warm-up,
seven fresh builds). No harness changes.

Samply still has no usable run on this host and macOS exposes no
counters, so native symbols, allocations and peak RSS remain **no
data**. Rankings use the driver's stage timers. Load stayed under 7
for the primary window. One early samples pass under a load spike
showed +20–60% elevations (trait/tokenizer/math/suspend) that vanished
on a clean rerun (all within ±2 ms of the previous report); those
spiked numbers are discarded, not reported below.

The warm-path deltas (±1 ms on a 7–14 ms cache-hit path) are noise. Two
deltas held across a second five-run window, so they are likely real but
small: 30,009-line cold +3% and 30,009-line signature edit +8–9%
(rerun median 131.61 ms). In the cold representative run the increase
sits mostly in `FolderIface` (31.58 → 42.76 ms, stable across four
runs here) with `Body` +4 ms; the signature-edit run spends
`Body` 36.4 + `FolderIface` 30.6 + `Collect` 24.3 ms. Plausible causes
are the two new embedded std modules (check misses 36 → 38) and the
#121 compiler-supplied rows riding on interfaces/collection — but at
+8–11 ms absolute on a 120–250 ms run, neither meets the flag bar (no
order-of-magnitude, no superlinearity: cold still scales 3.7× for 10×
lines). Small-size Wasm grew 185,128 → 186,920 B (+1.0%, the new std
surface); large-size Wasm is flat (1,843,544 → 1,843,538 B).

## Findings

- Nothing to flag: every stage, sample and pool ratio is within noise
  of the previous report except the two small cold/signature-edit
  increases above (+3%, +8%), which are an order of magnitude below the
  flag bar and scale sublinearly.
- Watch item for the orchestrator (not a flag): `FolderIface` at 30,009
  lines cold rose ~11 ms across stable runs; if the #121
  compiler-supplied rows attach per-interface work, that is where it
  shows. Revisit after the next solver change.
- The untimed remainder (scheduler/graph/cache/driver, 55.41 ms cold)
  stays a top-two row with no function-level owner; sampled symbols
  would still be the way to split it.
