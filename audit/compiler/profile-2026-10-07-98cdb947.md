# Compiler Profile: `98cdb947`

Date: 2026-10-07

Status: measurement only; nothing here changes accepted behavior. This checks
the implementation against [Design Overview](../../future-work/compiler/design-overview.md),
[Type Checking](../../future-work/compiler/type-checking.md), and
[Codegen](../../future-work/compiler/codegen.md).

This report profiles compiler commit `98cdb947`, which runs `cargo fmt` over
the compiler crates. Inspection found only formatter line wrapping and import
ordering; no expression, value or algorithm changed. The comparison baseline
is [`b4c14e39`](profile-2026-10-07-b4c14e39.md).

## Scope And Method

The release `hd_driver` benchmark ran 200 functions per folder (3,009 lines)
and 2,000 per folder (30,009 lines), covering cold, warm, all-private-body,
public-signature-and-caller, and comment edits. The 30k cold, warm, body and
comment numbers are medians of five runs captured by Samply. The external
signature harness ran once at each size and confirmed the cache counters.

The release `hd` binary ran every compiler sample, the four hand-written
benchmarks, and the generated 10,000-line package on V8 through Node. These
times are medians of five runs after one warm-up. `hd build` compiled the trait
sample without starting Node. Every program produced its expected output.

Samply captured 760 samples, but the release binary still exposed addresses
rather than function names. The largest exclusive address held 5.7% of
samples. The hot-function table therefore maps the driver's named stage timers
to their owning functions, as the previous report did. `Parse` is nested in
its owning stages, so its share overlaps them. Allocation counts and peak RSS
are **no data** because the current counters and profile do not expose them.

## Findings

1. No atrocious performance issue appears. The formatting-only compiler
   commit preserves output, cache hit counts, invalidation breadth, Wasm byte
   sizes and near-linear scaling.
2. The 30k cold median improved 4%; every 30k path is within ordinary run
   variation of the previous report. No regression can be attributed to
   `98cdb947`.
3. The existing implementation slips are unchanged: the temporary subset
   parser serves both full and interface work, and warm work is dominated by
   source skimming rather than a manifest fast path.
4. Signature invalidation remains correct and narrow at codegen: both modules
   recheck, but only the changed function and its caller re-emit.
5. Named native samples and allocation counts remain measurement gaps. A
   symbol-bearing profiling build is still needed before Samply can replace
   the stage-owner ranking.
