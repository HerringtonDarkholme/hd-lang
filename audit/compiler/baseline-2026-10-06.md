# Compiler And CLI Baseline, 2026-10-06

Status: a factual snapshot of the toy compiler and CLI (`src/`, `bin/`,
`lib/std/`) at commit `eac86a47` (task P1d). Nothing here is accepted
behavior, and nothing is a recommendation. Every number comes from a command
listed beside its table. The measuring machine was shared with other agents:
`uptime` load averages are noted where a time matters.

The compared texts are the specification under `spec/` (language, stdlib, and
CLI tiers), `spec/conformance/`, and `src/KNOWN_ISSUES.md`.

## 1. Summary

- Works end to end: parse, type-check, emit Wasm GC, run, test, build, REPL,
  packages, workspaces, dependencies, `hd new`, JSON output. The portable
  suite is green: 2,604 selected cases pass, 0 fail, and 617 Node tests pass.
- 12 conformance cases are known failures. Ten need `hd doc` or
  `hd new --pages`, one is a held feature, one is a missing runtime profile.
- Biggest gaps: no `hd doc` flags, no stack-overflow panic (F-161), the
  playground binds only `Console`, and 26 open findings in `src/KNOWN_ISSUES.md`
  (7 correctness, 15 runtime cost, 4 structure).
- Size: 73,618 lines of TypeScript in `src/`, 10,155 lines of hd in 35
  `lib/std` files.
- Spec: 5,603 rules (4,065 language, 1,247 stdlib, 291 CLI). A fixture cites
  1,825 of them by rule ID (32.6%): language 25.2%, stdlib 55.5%, CLI 37.5%.
- Speed: `run-portable` takes 65 s wall, the Node tests 31 s. The tiny program
  checks in about 0.3 s and builds in about 0.6 s as a CLI process. The type
  gate passes 13 of 13 cases.
- Runtime: hd release Wasm beats Node on fib (3.9 ms vs 5.8 ms). It is 2.5x
  to 10.9x slower than Node on sum, string, map and sort, and 2.5x to 4.5x
  slower than Python on string, map and sort.
- Footprint: tiny program 16,350 WAT bytes and 23 functions; one-test program
  3,143 bytes and 6 functions. The tiny package builds to 1,669 Wasm bytes.

## 8. Known Gaps And Design Debts For The Rewrite

Items 8.1 to 8.7 were requested. Items 8.8 and later are from
`src/KNOWN_ISSUES.md` or are my own findings, marked "own finding".

### 8.1 String join is O(L log n)

- Evidence: commit `b1dee393`. `join` appends by halves, so each byte is
  copied about log2(n) times. `replace` joins once, `repeat` doubles.
- Measured: the string-build microbenchmark takes 19.0 ms in hd, 5.7 ms in
  Node, 7.6 ms in Python (section 6.2). The commit records 5,160 ms before.
- True O(L) needs a `bytes_join`-style primitive. That is a spec decision
  for the owner. `bytes_concat` copies both operands into a new array.
- Related open findings: F-503 (interpolation concatenates pairwise).

### 8.2 Global type-intern caches grow without bound

- Evidence: commit `24adec54`. `src/types.ts:88` holds `PARSED_TYPES`
  and `src/types.ts:651` holds `ROW_KEYS`, both module-level `Map`s. A grep
  finds no `clear` or `delete` on either.
- Repro (own measurement): calling `parsedType` on distinct type strings,
  50,000 at a time, with `--expose-gc` and a collection before each reading:
  heap 7 MB, then 80, 152, 217, 296 MB after 50k, 100k, 150k, 200k roots. That
  is about 1.5 KB per type root, retained after GC.
- Repro through `ReplSession`: 60 inputs and four `reset()` calls moved heap
  from 42 MB to 44 MB after reset. `reset()` does not clear the caches. The
  growth per input is small, so a long session is the case that matters.

### 8.3 Panic locations depend on engine stack traces

- Evidence: `src/panic-locator.ts` reads `new Error().stack` with
  `Error.stackTraceLimit = 200` to find the Wasm frame under a host import
  (commits `91bbf300`, `2498eac2`, `eac86a47`). The locator parses the
  stack text, so a host whose engine gives no such frames gets no location.
  I ran only Node, so Safari and third-party hosts are not measured.
- F-161: unbounded recursion has no panic location and no `stack-exhausted`
  panic. Repro (`rec.hd`, `down(n + 1) + 1`): `hd rec.hd` exits 1 and prints a
  Node `RangeError: Maximum call stack size exceeded` with
  `wasm://wasm/...:wasm-function[17]` frames.

### 8.4 The usize-fallback panic note is not transitive
