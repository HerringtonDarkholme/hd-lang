## FAIL and N/A causes

Only what the output shows.

**One cause behind 35 FAIL lines.** The generated 10k-line package fails
`hd check` with `ambiguous-method` at `src/m001.hd:39:21` (and the same
shape in later modules: `Item1: Costed1, Costed1 fit this call`). Every metric
that needs a working generated package failed on it, so no value was measured:

- Pillar 1: edit-latency (2), cold-check, test-latency, recheck-precision (2).
- Pillar 2: resources (20, including the two warm 10k CPU and RSS lines), concurrency (3), disk, cache-contention compilation cache (2), cache-growth.
- Pillar 3: dead-code bytes per 1,000 lines.
- Gate: incremental-soundness.

**Other Pillar 1 failures**

- mistakes, answer-size, determinism, diag-location, fixit-safety: the scripts crashed with ENOENT on `test/metrics/mistakes`; the corpus lives at `bench/metrics/mistakes`.
- pathological deep-blocks and deep-parens: `nesting-too-deep` (the implementation limit) at scale 4 (deep-blocks) and scale 1 (deep-parens).
- pathological method-chain at 4x: `hd check` overflowed its stack and aborted.
- pathological large-enum-match growth exponent: 2.01 against 1.3 (102 ms at 2x, 330 ms at 4x).
- errors-per-run mixed: 2 of 10 mistakes reported (the file with 2 syntax errors).
- check-cost: checked 1011 ms against unchecked 573 ms (1.76x).
- dev-speed (2): the optimized work is within noise (under 50 ms) for fib, sum, string-build, map and sort, so the ratio is not judged and fails.

**Other Pillar 2 failures**

- startup, `hd check empty.hd` peak RSS: 14.1 MB against 10 MB.
- parallel-speedup: `hd check` has no option `--jobs=1`.

**Other Pillar 3 failures**

- proptest-perf cases per second: 28k/s against 100k/s.
- integration-test-perf: 71 ms setup per program (20 ms), growth exponent 1.028 (needs under 1), 68 ms per doc test (20 ms).
- runtime: geomean 1.62x Node (1.5x); sum 4.86x (3x).
- size-startup-heap: tiny Wasm 2399 B (2048 B); start to first output 42 ms (5 ms).
- host-call-overhead: Fs read_text! 31 µs (10 µs); list_dir! 41 µs (5 µs).
- serde-throughput: encode 0.05x and decode 0.08x of Node (0.5x).
- text-throughput: string build 0.20x and regex find_all 0.05x of Node (0.5x).
- long-run-memory: the simulated service reported no request, so no growth was measured.

**N/A (6 in pillars, none in the gate)**

- cache-contention dependency cache (2) and fetch-dedup: no help text names `HD_CACHE`.
- io-per-check: `fs_usage` and `dtruss` need root on macOS.
