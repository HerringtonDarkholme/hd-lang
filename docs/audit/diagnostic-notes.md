# Diagnostic Notes

Findings about error messages, codes, positions and fix-its, gathered while
building the Rust compiler. Owner rule (2026-10-08): log them here; do not
change the spec or the conformance fixtures for them. The compiler does what
it does until the owner picks items from this list.

| Date | Where | Finding | Today |
| --- | --- | --- | --- |
| 2026-10-10 | Native syscall cancellation (`cli.limit.time`, M21) | Epochs interrupt Wasm instructions; reactor and network waits use the absolute wall deadline. Unix and Windows Process/filesystem pipe I/O use nonblocking polling without pending I/O or detached mutation workers. A single blocked kernel filesystem call, remote SMB pipe open, blocking output write, or entropy syscall remains an OS limitation. Windows mode changes can require extra attribute rights; refusals remain OS errors, never blocking fallbacks. | Windows source and cross-target checks do not replace native Windows execution; platform-specific pipe tests require a Windows runner |
| 2026-10-10 | Darwin descriptor exhaustion (`cli.limit.time`, M21) | When every descriptor below 1024 is occupied, safe select or low-descriptor duplication cannot detect an empty FIFO writer disconnect. Poll fallback may return the wall timeout instead of empty EOF; data remains readable. Ordinary descriptor cases use select and pass native tests. | Owner accepted documenting this rare edge; no unsafe dynamic-select wrapper |
| 2026-10-17 | Duration constructors take a signed count (#507) | `Duration::milliseconds(n)` and `Duration::seconds(n)` keep their `i64` parameter, since the suffixes pass an `i64`. A negative `n` panics with `explicit-panic` in every build. Rust's constructors take unsigned counts, which the suffix signature would not match. | Panic on a negative count |
| 2026-10-17 | Duration `-` always panics (#507) | The issue allows a panic in debug and test builds. `a - b` with `a` shorter than `b` panics with `explicit-panic` in every build, as Rust's `Duration` does, so a release build cannot wrap to a negative value. | Panic in every build |
| 2026-10-17 | Duration text keeps a leading `+` (#507) | The `-` sign is gone from duration text. The optional `+` stays, as in Go, so `"+2s"` still parses. `"-5s"` and `"-0"` give `InvalidCharacter` at 0. | `+` kept, `-` an error |
| 2026-10-17 | Net timeout rule keeps its old ID (#507) | `std-net.timeout.zero` now says only that a zero timeout ends a wait at once. Renaming it to a zero-timeout ID touches `host/net.mjs` and `hd_run_wasmtime` comments, so the name stays stale. | ID kept |
| 2026-10-17 | Backoff factor below zero (#507) | `retry_with!` multiplies the delay by `factor: i32`. A negative factor now panics in `Duration::milliseconds` at the first growth, where it once panicked in `sleep!`. | Panic, no new rule |
| 2026-10-18 | `using!` outside a bang function (#350, `flow.using.async.driver`) | The binding's `dispose!` is the bang call, so the error is `bang-call-outside-suspension`, on the `using!` statement, with the generic text "a bang call needs a suspending function or closure". The text does not say that the dispose is the call. | Generic message |
| 2026-10-18 | `using` of an integer literal (#350) | `using n = 5` reports "usize does not implement Disposable": the literal takes its default type before the bound is checked, and the message does not name `using`. | Default-type message |
| 2026-10-18 | A discarded cold cancel (#519, `req.cancel.cold.discard`) | `job.cancel()` as a statement reports "a mut Suspend[CleanupEnd] value is discarded; handle it or write `_ := ...`". Code that meant to cancel wants `job.cancel!()`, and the text does not suggest the bang. | Generic must-use message |
| 2026-10-18 | `spec/tools/run-conformance.ts` over `scripts/hd-conformance.sh` (#519) | Every `runtime/panic` case fails with "exit 3 without a panic report": `hd FILE` prints its `panic: CODE:` line unindented, and the adapter rewrites only indented panic lines, so the runner reads `panic` as the category. The cargo conformance tests do not use this path. | TS runner fails panic cases |
| 2026-10-18 | `&mut T` to `&T` inside a type (#532, `ref.convert.weaken`) | Only an outer `&mut T`, or one in an optional, converts. Passing a `List[&mut User]` where a `List[&User]` is expected is `type-mismatch`, though a read through `&T` gives that very type. | Outer conversion only |
| 2026-10-18 | `is` on `dyn Any` values that hold references (#533, `expr.is.conversion`) | A reference converted to `dyn Any` is its `Ref` object, so `a is b` on two `dyn Any` values made from two references to one place compares the objects and is false. `ref.type.any-ref` makes a reference `AnyRef`, but no `is` rule lists references. | Emulation gap; no rule names it |
| 2026-10-18 | `&mut self` on a value parameter (#537, `fn.method.auto-address.fix`) | The fix-it for `p.shift(1)` with a value parameter `p` writes `mut p`, which makes the call change the callee's own copy; a caller who wanted its value changed needs `p: &mut Point`, which a fix-it cannot choose. | Fix-it writes `mut` |
| 2026-10-18 | A trait value against its own bound (#537, `trait.dyn.bound.available`) | `area_of(s)` for `s: dyn Shape`, where `Shape` has a `&self` method, says "Shape does not implement Shape": the message prints the trait value type as its trait and does not say which member is unavailable. | Message names no member |
| 2026-10-18 | Identity of an auto-addressed receiver (#537, `ref.identity.same-place`) | A call that takes a receiver's address draws the local's serial only when some `&` in the file names it (`BodyCx::ref_names` scans `&x`, not method calls). Otherwise each call's `&self` gets a fresh serial, so `self is other` inside two calls on one local can differ. | Fresh serial per call unless `&x` appears |
| 2026-10-19 | `trait.dyn.ref.bare-reference-method` reuses `dyn-member-unavailable` (#543) | `&e` on a bare `dyn Tr` is reported at the reference with the code of an unavailable member, and the message names no member. A reader looks for a call that is not there. | Code of the cause, not of the site |
| 2026-10-19 | `recursive-value-type` for a group (#544, `data.enum.no-recursion.group`) | Structs and enums that contain one another are one error, reported at the member whose module path, then name, sorts first, so the error may sit on a later declaration than the one a reader would fix. The fix-it writes `&` only in that member. | Name order |
| 2026-10-19 | Generic key solved from the provider scope (#562, `req.with.nearest`) | `total([1, 2])` for `fn total[T](xs: List[T]) -> i32 $ Repo[T]` inside `$.with(Repo[i32]=...)` is `missing-requirement` ("this needs `$ Repo[?]`"): the call's `T` is not solved from the list literal before the row check, so the message prints an unsolved key. `total::[i32]([1, 2])` checks. Data and reference providers alike. | Unsolved key |
| 2026-10-19 | A trait value reference as provider of a by-value trait (#562, `req.ref.share.no-trait-value-ref`) | `$.with(Label=label)` with `label: &dyn Label` reports "&Label does not implement Label": it shows the `dyn` reference as `&Label` and names no fix (`*label` installs the bare trait value). | Generic mismatch text |
| 2026-10-19 | `mutable-receiver-required` on an `Iterator[T]` value parameter (#563, `flow.for.iterator-place`) | The fix-it writes `mut source`. That makes the parameter a writable copy of the struct, whose `step` closure is the caller's, so advancing the copy still advances the caller's iterator. `&mut Iterator[T]` is the type the rest of std uses. | Writes `mut` |
| 2026-10-19 | `&mut` written for a binding that never changes (#570, `trait.dyn.ref.written.reference-fix`) | `t := Tally { n: 0 }` then `count(t)` with `count(c: &mut dyn Counter)` offers `&mut t`, which then reports `non-reassignable-binding` with its own fix-it, `let mut t = ...`. Two rounds of `hd check --fix`, and the first one is rejected as unsafe since it brings a new diagnostic, so `hd check --fix` applies neither. | Two-step fix |
| 2026-10-19 | `$.use(K)` at a script's top level for a host trait other than `Console` (seen testing #571, `module.init.script-profile`) | `x := $.use(Args)` or `$.use(Clock).now()` in a script compiles to "unsupported: stage Emit: a provider of `dyn #130`, which this function's row does not cover", with the trait printed as a number. A call of a function whose row has the key (`now()`) works. Not caused by #571: `Args` has no reference receiver. | Unsupported at Emit |
| 2026-10-23 | `use std.rt.memory.{Ptr}` then a `Ptr { address: 0 }` literal in user code (seen adding typed memory, `module.rt.ptr.decl`) | After the expected `std-only-use`, the literal also reports a cascaded `unknown-type` for `Ptr`; the second error is only a consequence of the first. | Cascaded error |
| 2026-10-29 | `downcast_mut` on a read-only `*dyn` (#988, `trait.downcast.mutable-receiver`) | `not-writable` says "`downcast_mut` takes `&mut self`", the checker's generic receiver text; the receiver is now `*mut self`. | Stale receiver text |
| 2026-10-29 | `downcast_ref` on a local `&dyn` built from a field, `let erased: &dyn Inspectable = &p.b` (#988, `trait.downcast.counted-receiver`) | `local-reference-escapes` offers "write `*` for its `&`", which turns `&p.b` into a field-backed counted reference and a second error. | Fix-it leads to a second error; suggest boxing at the declaration |
